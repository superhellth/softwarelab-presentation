tour.json is the on-disk contract

Waypoints, radii, assets, breadcrumb trail — written once, read by both modes.

  "waypoints": [
    { "lat": 50.778, "lon": 6.089,
      "prefetchRadius": 25, "activeRadius": 10 }

    { "id": "knight-1", "assets": ["sprite-1", "audio-1"] }
  ],
  "breadcrumb": [
    { "lat": 50.778, "lon": 6.089 }
  ]
}

Lat/lon appears only here — everything downstream is world-space meters.

what worked

Three LLM prototypes beat trusting one blindly

Same plan into ChatGPT, Claude and Gemini — compared on UX and code, borrowed the best ideas from each.

AI reflection

The plan forced the AI to read our contract, not invent its own

  • Every component started as a plan.md, then three competing prototypes — never one AI's first answer, unreviewed.
  • Building inside an existing framework made the plan-review step matter more than on greenfield work.
summary

What we presented

  • 10 isolated, individually-tested components → composed into authoring + viewing modes
  • Pure world-space logic, proven deterministically against real outdoor recordings
  • Zero backend — a QR code and an everyday cloud drive is the whole deployment
  • Hardest part: agreeing the shared contract before writing any component

Starting point for discussion — happy to take questions on any of it.
